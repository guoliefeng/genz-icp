# GenZ-ICP 项目中文导读

这份文档用于快速理解本仓库在 ROS1 下的主要流程，尤其是 Yangpu 数据集地图定位验证部分。

## 目录结构

- `cpp/genz_icp/core/`
  - GenZ-ICP 的核心算法模块。
  - `Registration.*`：ICP 配准求解，负责 scan-to-map 对齐。
  - `VoxelHashMap.*`：体素哈希地图，负责近邻搜索和局部平面判断。
  - `Preprocessing.*`：点云裁剪、体素下采样等预处理。

- `cpp/genz_icp/pipeline/`
  - 原始 GenZ-ICP 里程计流水线。
  - 输入连续点云，输出相对里程计轨迹。
  - 这个流水线默认是在线建局部地图，不直接使用外部 `global.pcd`。

- `ros/ros1/`
  - 原项目 ROS1 节点封装。
  - `OdometryServer.cpp`：订阅点云，调用 `pipeline::GenZICP`，发布 `/genz/odometry`、`/genz/trajectory` 和调试点云。

- `ros/tools/Loc_Map.cpp`
  - 为 Yangpu 数据集新增的地图定位验证节点。
  - 支持两种模式：
    - 离线模式：节点自己读 bag，适合复现实验和写 CSV。
    - 在线模式：launch 启动节点和 RViz，你手动 `rosbag play`，节点只订阅话题，不播放 bag。
  - 在线模式是当前推荐工作流。
  - 更详细的流程图和调试说明见 `docs/YangpuMapLocalization流程说明.md`。

- `ros/launch/yangpu_map_localization.launch`
  - Yangpu 在线地图定位 launch。
  - 默认不播放 bag。
  - 默认打开 RViz。
  - 可选 `record:=true` 录制评估用小 bag。

- `ros/rviz/yangpu_map_localization.rviz`
  - RViz 配置。
  - 显示全局地图、当前配准点云、轨迹和当前位姿。

## 原始 ROS 里程计节点数据流

`ros/ros1/OdometryServer.cpp` 的流程如下：

1. 从参数服务器读取 GenZ-ICP 参数。
2. 订阅 `pointcloud_topic`。
3. 每收到一帧 `sensor_msgs/PointCloud2`：
   - 转成 `std::vector<Eigen::Vector3d>`。
   - 可选读取点内时间戳做 deskew。
   - 调用 `odometry_.RegisterFrame(...)`。
   - 从 `odometry_.poses().back()` 取当前里程计位姿。
   - 发布 `/genz/odometry` 和 `/genz/trajectory`。
   - 可选发布局部地图、平面点、非平面点。

这个节点适合“LiDAR odometry”，不适合直接验证外部全局地图定位。

## Yangpu 地图定位节点数据流

`ros/tools/Loc_Map.cpp` 的在线模式流程如下：

1. 启动节点。
2. 订阅：
   - `/localization/ins`
   - `/lidar_preprocessor/meta_cloud`
3. 第一帧 INS 到达后：
   - 将它作为初始位姿。
   - 以它为中心裁剪 PCD 地图。
   - 将 PCD 点云写入 `VoxelHashMap`，作为固定 `global_map`。
   - 发布 `/genz_loc/global_map`。
4. 每收到一帧融合点云：
   - 点云转 Eigen。
   - 距离裁剪。
   - 体素下采样。
   - `PredictPose()` 生成预测位姿：第一帧永远用 INS；后续由 `use_ins_prediction` 决定，用 INS 帧间增量或 ICP 恒速模型。
   - 调用 `Registration::RegisterFrame(...)` 对固定 `global_map` 做 scan-to-global-map 观测更新。
   - 用最终定位结果更新 rolling `local_map`。
   - 发布 `/genz_loc/odometry`。
   - 发布 `/genz_loc/trajectory` 和 `/genz_loc/ins_trajectory`。
   - 发布 `/genz_loc/local_map`、`/genz_loc/aligned_scan`、平面点和非平面点给 RViz。
   - 写 CSV 方便误差分析。

## 推荐启动方式

终端 1，启动节点和 RViz：

```bash
source /home/guoli/proj/genz-icp_ws/devel/setup.bash
roslaunch genz_icp yangpu_map_localization.launch rviz:=true record:=true
```

如果想关闭 INS 帧间预测，让首帧仍用 INS、后续预测方式和 `OdometryServer.cpp` 一样使用 ICP 恒速模型：

```bash
roslaunch genz_icp yangpu_map_localization.launch rviz:=true record:=false use_ins_prediction:=false
```

终端 2，手动播放 bag：

```bash
cd /home/guoli/data/yangpu/A203/A203
rosbag play 2026-06-03-1*.bag
```

## 评估输出

默认 CSV：

```bash
/tmp/yangpu_loc_genz_icp.csv
```

默认评估 bag：

```bash
/home/guoli/data/yangpu/loc/yangpu_loc_genz_icp_eval2.bag
```

bag 默认只录：

- `/genz_loc/odometry`
- `/localization/ins`

这样不会录点云，体积会小很多。

## evo 评估命令

XY 平面 APE：

```bash
evo_ape bag /home/guoli/data/yangpu/loc/yangpu_loc_genz_icp_eval2.bag \
  /localization/ins /genz_loc/odometry \
  -r trans_part --project_to_plane xy --t_max_diff 0.05 --plot
```

轨迹对比：

```bash
evo_traj bag /home/guoli/data/yangpu/loc/yangpu_loc_genz_icp_eval2.bag \
  /localization/ins /genz_loc/odometry \
  --ref /localization/ins --plot
```

10 米相对误差：

```bash
evo_rpe bag /home/guoli/data/yangpu/loc/yangpu_loc_genz_icp_eval2.bag \
  /localization/ins /genz_loc/odometry \
  -r trans_part --project_to_plane xy -d 10 -u m --t_max_diff 0.05 --plot
```

## 常见现象

- RViz 里地图像圆圈：
  - 说明 `map_radius` 大于 0，只加载了初始位置附近局部地图。
  - 如果车辆开出这个范围，ICP 没有地图点可匹配，会漂移。
  - 当前 launch 默认使用局部半径；如果要加载完整地图，可启动时加 `map_radius:=0.0`。

- 3D APE 比 XY APE 大：
  - 之前评估发现 Z 方向有约 1 米级系统偏差。
  - 对平面车辆定位，优先看 `--project_to_plane xy`。

- bag 体积很大：
  - 不要录 `/genz_loc/trajectory` 和点云。
  - 当前 launch 的 `record:=true` 只录 odometry 和 INS。
